## Phase 16 — issues found by the integration (and fixed)

| ID | Status | Finding |
|----|--------|---------|
| CI-48 | 🟢 | **The vertical reflow re-timed scenes but not their animation** (Phase 14): `verticalReflow` re-plans each scene's duration from its speech but kept the original `animation` events, so any scene whose spoken length came out shorter than its plan produced a manifest that failed its own schema (`animation … ends at 2.8s, past the scene's 1.9s`). The shorts fixtures never shrank a scene, so the engine tests could not see it. Fixed by uniformly scaling each event's `atSec`/`durationSec` into the new scene length (still ordered, still inside the scene), with a layout note when the scale is meaningful, and a regression test that speaks a scene at 40% of its plan. Lesson: when a transform re-times a container, everything timed relative to that container must move with it — and a fixture suite only proves what its fixtures exercise. |
| CI-49 | 🟢 | **Type sized for a 16:9 frame cannot fit a 9:16 frame** (Phase 14/9 interplay): the compositor derives type size from the frame's *height* (`sizeFactor × resolution.height`), so re-composing a scene into the tall canvas made text ~1.8× larger while the box got ~0.56× narrower — every text card overflowed and QA blocked (`visual_layout_invalid`). `SceneTextSchema` had no way to say "smaller here". Fixed with an optional `sizeScale` (default 1, so 16:9 behaviour is unchanged): the reflow computes `canvas.width/source.height ÷ canvas.height/source.width` (never enlarging), which preserves the long form's fit and keeps type above the readability floor at the vertical canvas. Lesson: when a check is calibrated at one aspect ratio, a re-composition for another must carry an explicit size term, not inherit one. |
| CI-50 | 🟢 | **The short's canvas inherited the long form's render config** (Phase 16 wiring): the worker built the vertical canvas by swapping `config.render.width/height`, which at the test's toy resolution (192×108) designed the vertical manifest at 108×192 — text measured ~8.8 px and QA rightly refused it. The platform's vertical canvas is a constant (1080×1920), and at production configs the swap only coincidentally matched it. Fixed: the worker uses `VERTICAL_CANVAS` for both the layout and the vertical render config (tests inject a size-matched scripted FFmpeg via a new `shortFfmpeg` option). Lesson: derive a design surface from its own spec, not from a neighbour's config — a swap is only correct where the two specs happen to agree. |
| CI-51 | 🟢 | **A stale build output inside `src/` silently shadowed the source** (tooling): an earlier mis-targeted `tsc` invocation emitted `packages/shorts/src/*.js(d.ts)` next to the sources; the workspace alias resolves `@nexus/shorts` to `src/index.ts`, whose `./layout.js` import then loaded the **stale compiled file** — the animation fix "didn't work" until the strays were found and deleted. Lesson: `.js` import specifiers + emitted-in-place outputs = shadowed sources; `format:check`/lint pass, tests pass, and the fix is invisible. Deleted the strays; the packages emit to `dist/` only. |
